# 撮影設計 AI / KOBAN Prototype v4

## 今回の追加
- 案件準備ステップを追加
- 案件の基本情報は「手入力 / コピペ / 資料共有」の混在を想定
- 台割・ワイヤー・デザイン・コンセプトを「撮影設計にクリティカルな資料」として別レイヤー化
- AIが理解した案件前提を確認してから次工程へ進む導線
- 台割上の「素材領域確認」ステップを追加
- AIが検出した領域候補をクリックして選択
- 素材タイプを「写真 / 動画 / 図版」に分類
- 領域ごとに用途・AIへの補足を編集
- Figmaは必須ではなく、PDF / PPTX / 画像などと並ぶオプション扱い
- 素材領域確認後、「カット設計へ進む」で既存の香盤UIへ接続するデモ導線

## 今後
今回の「台割プレビュー」はUI検証用のモックです。
次段階では、実ファイルを解析してページ画像を表示し、AI候補領域を実際に抽出する処理へ差し替える想定です。

## v29 変更：画像生成を実接続できる最小構成
- `server.mjs` を追加
- `POST /api/cut-images` を実装
- ブラウザにはAPIキーを置かず、サーバー側の `OPENAI_API_KEY` を使用
- 1カットにつき「標準／引き／演出強め」の3候補を生成
- フロント側の既存「AI／Webから探す」ポップアップと接続可能
- Web参考画像は別プロバイダーとして同じ `candidates[]` 契約に追加できる
- OpenAIのResponses APIでは画像生成ツールを利用でき、生成結果を画像として受け取れる構成を採用

### ローカル接続
1. Node.js 20+ を用意
2. `npm install`
3. `.env` に `OPENAI_API_KEY` を設定
4. `npm start`
5. KOBANの「接続設定」で `http://localhost:8787/api/cut-images` を指定

※このプロトタイプのブラウザHTMLはAPIキーを保持しません。


## v30 変更：AI＋Web候補を同一の候補レイヤーへ統合
- `/api/cut-images` を AI / Web / AI＋Web の3モードに対応
- AI生成は3パターン（標準／引き／演出強め）
- Webは `WEB_SEARCH_ENDPOINT` を任意指定できるプロバイダー方式
- ブラウザから直接Web検索サイトをスクレイピングせず、バックエンドの検索プロバイダーから `candidates[]` を受け取る
- 画像候補のデータ形式を統一：`src / title / reason / source`
- これにより③のUIは「AIかWebか」を意識せず、候補を比較して選ぶだけにできる
- Web画像を実運用で利用する場合は、利用規約・ライセンス・出典表示の扱いを検索プロバイダー側で設計する
